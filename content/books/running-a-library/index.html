Running a library

Five chapters that take a repository from nothing to a gated, reviewable library of pages, for whoever sets one up and keeps it in order, human or agent.

The chapters

The order follows the life of a library: it has to exist before it has pages, it has pages before anything checks them, it is checked before anyone reviews it, and it is worth extending only once the core is familiar.

  1. Install a library — the engine on your machine, the kit in your repository, and the four commands you will run every day. Everything after assumes a library exists.
  2. Genres and voice — choosing what a page is, scaffolding it, writing it in the right register, and saying whether it is still true. The first thing you do in a library is write a page.
  3. The gate — what ckit check runs, in order, what each failure looks like, and why none is ever fixed for you. It comes after writing because its messages only make sense once you have pages to break.
  4. The review loop — a reader's notes in the browser, a file beside the page, and an agent answering them later. It needs the gate, because the gate is what keeps notes attached to the text they are about.
  5. Extending the kit — the ten kit.json keys through which a library adds genres, checks, generated files and shell pages; how a layer installs itself; moving a 0.3 library across; publishing under a path. Last, because every extension reuses a mechanism the earlier chapters teach.

How to read it

In order. Each chapter assumes only the ones before it, and every section ends with a check-yourself: open it after you have answered in your head. Terms with a dashed underline are concepts; hover one to read its definition without leaving the chapter.

The examples follow one small library about bird-watching, so that the same pages and the same log carry through from the first chapter to the last. Every command output shown was produced by running the command.

What you need

A terminal, git, Python 3.10 or newer, and node. uv makes installing the engine one line; without it you clone the repository instead. Node runs the book verifier, and the gate asks for it whenever the library has a content/books/ directory, which ckit init always creates, so have it installed from the start.
