The review loop

Status: LIVE — you leave able to leave notes on a rendered page, find them from any agent session later, and close each one with a reply the reader can check.

§1 · Annotate in the browser

Serve the library with make docs and open any page. Bottom right is ✎ Annotate. Turn it on and a panel opens listing the page's notes. Then there are two ways to leave one:

  • On a passage. Select some prose; a ＋ Comment on selection button appears. Write the note and save it.
  • On the page as a whole. Press ＋ Page note in the panel, for something about the page's shape, its genre or its status rather than one sentence.

The first time, the browser asks for your name and remembers it, because every thread needs an author. The panel shows each thread with its state, its quote and its replies, marks a thread whose quote can no longer be found as a stale anchor, and offers Withdraw on open threads and Reopen on closed ones.

The button is there only because the engine is serving the page. On load, the shell asks the server a question (/__annotations/ping); the engine answers, and only then does the shell load the annotation layer. A static host answers "not found", so a published copy of the library never grows the button, and no reader of it can annotate by accident.

Check-yourself: why can't a reader of the exported, published site leave a note?
There is no engine behind it to write the note down. The ping gets a "not found", so the shell never loads the annotation layer and the button never appears.

§2 · The sidecar

A saved note becomes a file beside the page, committed with it. A flat page's sidecar is named after the page; a folder page's is named after its index.html:

PageIts sidecar
content/notes/swifts-follow-weather.htmlcontent/notes/swifts-follow-weather.annotations.json
content/concepts/flyway/index.htmlcontent/concepts/flyway/index.annotations.json

Inside is a list of threads. Each has an id, an author, a date, a state, a body, its replies, and a target: the quoted passage, as the W3C Web Annotation TextQuoteSelector (the exact text, and up to 32 characters either side of it so a repeated phrase can be told apart), or null for a page note. The quote is stored as text, not as a position in the markup, so the page can keep changing around it.

That file is the whole channel. No server has to stay up and no agent has to be listening: the note survives in the repository until someone acts on it, and when they do, the thread and its reply stay in the file for good.

Check-yourself: where is the sidecar for /content/concepts/flyway/, and what goes in its target for a note about the whole page?
content/concepts/flyway/index.annotations.json; the target is null.

§3 · ckit annotations

The same threads, from the command line, in any session, on any clone:

$ ckit annotations list
open      /content/notes/swifts-follow-weather.html  t-20260922-7b8ecb  [sam]
          ▸ arrive with the first warm front
          Which front? Say how you would see it on a forecast.
VerbDoes
list [--state …] [--json]threads across the library; open ones unless you ask for addressed, declined, withdrawn or all
show <page>one page's threads, in every state
add <page> --author --body [--quote]open a thread; refused if the quote is not on the page
reply <page> <id> --author --body [--state]reply, and optionally move the thread's state
state <page> <id> <state> --authormove the state without a reply
checkvalidate every sidecar and its anchors

A page is named the way the browser names it (/content/notes/swifts-follow-weather.html, /content/concepts/flyway/) or by its path in the repository.

Check-yourself: how do you see every thread anyone has already closed as addressed?
ckit annotations list --state addressed, or --state all for everything.

§4 · /address

An agent works through open threads with the /address skill, which ckit init linked into the repository. The loop:

  1. List what is open: ckit annotations list.
  2. Read the page, not just the quote. Find the passage in context and read the genre's voice, because the fix has to stay in register: a note on a concept's definition is not answered by adding a paragraph under it.
  3. Decide, then do exactly one of two things. Address it: edit the page, then reply saying what changed, precisely enough to check without a diff, with --state addressed. Or decline it: reply with the reason, with --state declined. Nothing in between, and never "addressed" for a partial fix.
  4. Run the gate: ckit lint, then make check.
  5. Commit the page and its sidecar together, one commit per page, so the reviewer reviews page-sized changes.
$ ckit annotations reply /content/notes/swifts-follow-weather.html t-20260922-7b8ecb \
    --author "agent:claude" --state addressed \
    --body "Named the front: the first day the overnight low stays above 10 °C."
t-20260922-7b8ecb → addressed

A few rules keep the file trustworthy. Never delete a thread and never edit a sidecar by hand; state moves only through the browser or ckit annotations. Reply as yourself, agent:<name>, so the record shows who acted. Withdrawing is the reader's move, not the agent's. And when a thread asks for a number, the answer gives the number with its source, or says nothing supports one yet and leaves the thread open.

Check-yourself: a reader asks for a concept's definition to include this year's swift count. What do you do?
Decline, with the reason: a concept's definition must stay true when the count changes. The reply can offer what the genre allows, the count below the definition with its source.

§5 · What the gate holds you to

The previous chapter showed this failure from the gate's side. From the author's side it is one habit: address before you edit. If the page you are about to rewrite has open threads, answer them in the same change. Rewrite a passage an open thread quotes, and leave the thread open, and the gate goes red with a stale anchor until the thread is answered.

The gate also refuses a declined thread with no reason in its replies, a sidecar whose page has gone (an orphan), and a sidecar that names the wrong page. Closed threads keep their quotes as history, unchecked.

Check-yourself: you are rewriting a page with two open threads, one on a paragraph you are rewriting and one on a paragraph you are keeping. What has to happen in this commit?
The thread on the rewritten paragraph must be addressed (or declined, with its reason) in the same change. The other can stay open: its quote is still on the page.
