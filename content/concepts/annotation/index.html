Annotation

Definition of record. A reader's comment on a page, kept in a file beside it, so the reader and the agent who answers never need to be there at the same time.

ANNOTATION — definition of record
An annotation is a thread on a page: a comment on a quoted passage, or on the whole page, with its replies. It is stored in a sidecar, a committed file beside the page, and anchored by the quoted text and a little of the text around it, not by the page's markup. It is one of two kinds. A question is opened by a reader and waits until whoever acts on the page addresses or declines it. A flag is left by an agent on a passage it wrote beyond its source; it rests as noted, asking nothing until the reader keeps it or asks for a change. Its five states are open, noted, addressed, declined and withdrawn. Nothing has to be running for it to survive: the file is the only channel between the two sides.

Why it matters

Review usually needs both sides present: a live comment tool, a pull request someone is watching, a chat. Pages written by agents are read later, by people whose time does not line up with any agent's session. An annotation kept in a file beside the page, in the repository, outlives both the reading and the session that answers it, and the whole exchange becomes part of the history.

Anchoring by quote, not by position, lets a page keep changing while its annotations wait. A CSS path breaks as soon as a paragraph is added above it; a quoted sentence can be found for as long as the sentence exists. The shape is the W3C Web Annotation TextQuoteSelector: the exact text, plus up to 32 characters before and after it to tell repeated passages apart.

A served page shows its waiting annotations where they sit: each quoted passage is underlined, and a click on it opens the thread. The underline is drawn over the page's own text, never inserted into it, so the text a reader sees and quotes is the text the page carries.

Worked example

A reader of a bird-watching page selects "arrive with the first warm front" and asks which front. The engine writes content/notes/swifts-follow-weather.annotations.json:

{
  "version": 1,
  "page": "/content/notes/swifts-follow-weather.html",
  "threads": [
    {
      "id": "t-20260922-7b8ecb",
      "created": "2026-09-22T20:43:59Z",
      "author": "sam",
      "state": "open",
      "target": {
        "type": "TextQuoteSelector",
        "exact": "arrive with the first warm front",
        "prefix": "",
        "suffix": ""
      },
      "body": "Which front? Say how you would see it on a forecast.",
      "replies": []
    }
  ]
}

Days later, an agent runs ckit annotations list, rewrites the sentence to name the front, and replies in the thread with --state addressed. The reply says what changed. The thread stays in the file, with its reply, for good.

The loop runs the other way too. Writing a longer entry on the same birds, an agent adds a paragraph the source never said, and leaves a flag on it: --kind flag --label "worked example". The flag rests as noted. The passage is marked on the page and listed on the review page, and no one is waiting. Weeks later the reader presses Keep under it, or Ask for a change, and the thread opens with that instruction for the next agent.

Common trap

Editing the page before answering the annotations on it. An open thread's quote must stay on the page. Rewrite that sentence first and the gate fails: 
content/notes/swifts-follow-weather.annotations.json: thread t-20260922-7b8ecb has a STALE anchor — 'arrive with the first warm front' is no longer on the page
A dropped annotation is not an answered one. Address the thread, or decline it with the reason, in the same change that rewrites its passage. Once a thread is closed, its quote is history and is not checked: acting on an annotation usually changes the text it quoted. A noted flag whose passage was rewritten is named as stale by the lint and never fails it: withdraw the flag, and flag the new passage if it still goes beyond the source.
