Definition of record. The one command that decides whether a library may land, and why it reports instead of repairing.

GATE — definition of record
The gate is the command ckit check, run before anything lands. It fails when the engine version the repository pins differs from the engine running, when the shell is missing, when a kit.json declaration does not hold, when a generated index differs from what the content would generate, when a page breaks its form or its genre's checks, when an open annotation has lost its quoted passage, or when a book does not verify. It reports every problem and repairs none.

Why it matters

A rule nothing checks is a suggestion, and suggestions drift. The gate is where a library's rules stop being suggestions: it is fast (seconds), it needs no network, and it is the same command locally and in CI, so a page that passes on one machine passes on every machine.

It never rewrites. ckit lint regenerates the indices (the catalog, the search index, the backlinks, each book's navigation, the chronicle when a record is declared, and whatever a registered generator writes); ckit check only compares them with what the content would produce now. A commit that changed a title and forgot to regenerate is caught at the commit that caused it, not silently repaired later on someone else's machine.

In a library, make check runs one more thing first: make kit-verify, which hashes the vendored kit/ and compares it with the hash in kit/PIN, so an in-place edit of the shared rules fails too.

Worked example

In a bird-watching library, an author scaffolds a note and a concept and runs the gate straight away:

$ ckit check
indices out of date — run `ckit nav` (or `ckit lint`) and commit the result:
  content/catalog.json
  content/search-index.json
content lint clean — 2 file(s)
content check failed: indices

Exit status 1. The two new pages are not in the catalog yet. The gate still ran the lint, which found nothing else, and named the failed stage at the end. ckit lint writes the two files, the author commits them with the pages, and the gate passes:

$ ckit check
content lint clean — 2 file(s)
content check ok

Common trap

Running ckit lint and calling it checked. Lint regenerates the indices before it reports, so it can never find them stale; it also skips the engine pin, the declarations and the book verifier. Lint is the author's tool while writing. The gate is ckit check (or make check, which adds the kit's hash), and it is the only one whose green means anything to the next person.

Related concepts

The gate enforces each genre's checks, holds open annotations to their passages, keeps the chronicle current, and runs whatever a repository registers through an extension point. Every check in it is held to the design law.
