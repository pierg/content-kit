GENRE — definition of record
A genre is the kind of page a page is, decided by where the page lives in the content tree. It carries a structure (a directory, a layout and a skeleton to start from), a voice (a register, an assumed reader and the moves that are forbidden) and the checks the gate runs on every page of that kind. A page that lives under no genre is an error, not a default.

Why it matters

An agent cannot usefully be told to "write well". It can be told that a page is a concept: impersonal, present tense, a definition first, no running result inside the definition. The genre turns a vague instruction into a specific one, and it does so before the first sentence is written, because choosing where the file goes is the first act of writing it.

Classifying by path rather than by a field inside the page removes a disagreement before it can happen. A page cannot claim to be a note while sitting among the concepts; there is no front matter to fall out of step with the file's location. The same table that classifies pages also builds the sidebar, the landing page and the search filters, so a genre a repository adds shows up everywhere a core one does.

Part of the voice is checkable and is checked: a word bound, a ban on sections, a required definition, a known status, a forbidden forward link. The rest (register, reader) is judged by whoever reads the page. Each genre's rules say which is which.

Worked example

A cooking library has a note at content/notes/salt-early.html claiming that meat salted a day ahead browns better than meat salted at the pan. It is one claim with its reason, under 400 words, and it passes.

Then the author adds a section on salt types and another on timing for fish. The lint answers with the genre's own rule:

content/notes/salt-early.html: note has <h2> sections — a note is one claim; promote it

The fix is not to delete the headings. The page has become an entry, so it moves to content/entries/salt-early/index.html, where sections are expected and the register is analytical. If "dry brine" then needs explaining on a second page, it becomes a concept of its own, and both pages link to it instead of explaining it twice.

Paths are under the content directory. Four layouts cover them all: flat, folder, book index and book page. A repository adds or overrides genres in kit.json.

Common trap

Taking the checks for the voice. The lint checks proxies (length, sections, a definition, a known status), so a page can pass every one of them and still read in the wrong register: a hub that explains, a concept that argues, a note that hedges. Green says the page has the genre's shape. Whether it has the genre's voice is a reader's judgment, which is why the voice is written down for every genre and printed when the page is scaffolded.

Related concepts

A genre starts every page from its skeleton, is enforced by the gate, and can be added to through an extension point.
