SKELETON — definition of record
A skeleton is the starting file of a genre: an HTML page that already links the shell, carries a status line, holds the genre's parts in their order, and says in placeholder prose what goes in each. ckit new <genre> <slug> copies it to the path the genre names, and the author replaces every placeholder.

Why it matters

The cheapest way to keep a page inside the contract is to start it there. A skeleton already loads /shell/lib.css and /shell/lib.js, already has a first <p class="sub"> with a status word, and already has the definition block a concept needs or the backlinks list a related page ends with. The author begins with a page that passes the gate and has to write their way out of it, rather than beginning from a blank file and writing their way in.

This is tested, not assumed: the engine's selftest scaffolds one page of every core genre through ckit new and fails if any of them does not lint clean.

Worked example

In a bird-watching library:

$ ckit new concept flyway --title "Flyway"
created content/concepts/flyway/index.html
concept — impersonal, present tense, timeless
  reader:    has met the term and wants it pinned down
  forbidden: a definition that depends on a running result — the defn must survive the results changing
  checked:   status=True, max_words=1500, require_defn=True

The new file has Flyway in its <title> and <h1>, an opening figure slot, a blockquote.defn with a placeholder definition, and sections for a worked example, the common trap, related concepts and a backlinks list. The author fills each in the concept's register, deletes what the concept does not need, and keeps the definition block, which the gate requires.

A folder genre's skeleton may bring files with it: a new entry arrives with a source.json beside it, for an entry that reads an external paper. An entry that does not can delete it.

Common trap

Leaving a placeholder standing. The skeleton's own text passes the lint (that is the point of it), so a page whose status line still promises "one-line orientation" passes the gate too. The gate cannot tell placeholder prose from finished prose. Every sentence a skeleton brings is an instruction to replace it.

Related concepts

Every genre names its skeleton. A genre a repository declares through an extension point names one too: the engine looks for it among the shell's skeletons first, then from the repository root, so a layer can ship its skeletons beside its genre file.
